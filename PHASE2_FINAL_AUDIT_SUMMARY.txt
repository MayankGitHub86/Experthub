STEP 5: ORPHAN PREVENTION AUDIT ⛔
================================================================================

THEORY: E11000 cleanup prevents orphaned units

IMPLEMENTATION:
  if (error.code === 11000) {
    try {
      await this.deleteMany({ holdId }, { session: session || undefined });
    } catch (cleanupErr) {
      console.error('Error cleaning up:', cleanupErr);
    }
  }

ASSESSMENT: ⛔ UNRELIABLE

Reason 1: Cleanup is a separate operation after insertMany() fails
  - Units 1-4 inserted successfully
  - Unit 5 conflicts with E11000
  - insertMany() stops (ordered=true)
  - deleteMany() runs, but units 1-4 already committed on standalone
  - Result: Partial units remain in database

Reason 2: Cleanup not protected by transaction on standalone
  - If standalone MongoDB, session does NOT provide atomicity
  - Cleanup can fail or be interrupted
  - Orphaned units can persist permanently

Reason 3: Never tested under actual concurrency
  - No test executed (all failed during setup)
  - No verification of actual cleanup behavior
  - No verification that orphans do not block future bookings

VERDICT: Orphan prevention is NOT VERIFIED and likely unreliable on standalone.
